디자인 패턴은 반복되는 문제를 해결하기 위한 표준적인 방법입니다. 너무 복잡하게 생각할 필요 없이, 자주 쓰이는 것부터 알아봅시다.

## 1. Singleton

인스턴스를 하나만 생성하는 패턴입니다.

```typescript
class AppConfig {
  private static instance: AppConfig;
  private constructor() {}

  static getInstance(): AppConfig {
    if (!AppConfig.instance) {
      AppConfig.instance = new AppConfig();
    }
    return AppConfig.instance;
  }
}
```

## 2. Observer

상태 변경을 구독자에게 자동으로 알리는 패턴입니다.

```typescript
class EventBus {
  private listeners: Map<string, Function[]> = new Map();

  on(event: string, callback: Function) {
    const list = this.listeners.get(event) || [];
    list.push(callback);
    this.listeners.set(event, list);
  }

  emit(event: string, data: unknown) {
    this.listeners.get(event)?.forEach((cb) => cb(data));
  }
}
```

## 3. Factory

객체 생성 로직을 캡슐화하는 패턴입니다.

```typescript
function createUser(role: "admin" | "user") {
  const base = { createdAt: new Date(), active: true };
  return role === "admin"
    ? { ...base, role, permissions: ["read", "write", "delete"] }
    : { ...base, role, permissions: ["read"] };
}
```

## 4. Strategy

알고리즘을 런타임에 교체할 수 있는 패턴입니다.

```typescript
type SortStrategy<T> = (a: T, b: T) => number;

function sort<T>(arr: T[], strategy: SortStrategy<T>): T[] {
  return [...arr].sort(strategy);
}

const byName = (a: { name: string }, b: { name: string }) =>
  a.name.localeCompare(b.name);
```

## 5. Decorator

기능을 동적으로 추가하는 패턴입니다.

```typescript
function log<T extends (...args: any[]) => any>(fn: T) {
  return (...args: Parameters<T>): ReturnType<T> => {
    console.log(` 호출: ${fn.name}`, args);
    return fn(...args);
  };
}

const add = (a: number, b: number) => a + b;
const loggedAdd = log(add);
loggedAdd(1, 2); // 로그 출력 후 3 반환
```

## 마무리

이 패턴들은 만능이 아닙니다. 상황에 맞게 필요한 것만 골라 쓰는 것이 중요합니다. 과도한 패턴 사용은 복잡성만 높일 뿐입니다.
